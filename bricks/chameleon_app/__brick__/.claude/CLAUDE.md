## How to run

```bash
fvm flutter pub get
fvm flutter run --flavor development -t lib/main_development.dart
fvm flutter analyze      # MUST pass before you consider work done
fvm dart format .
fvm dart run build_runner build --delete-conflicting-outputs
```

Always run `flutter analyze`, `dart format .`, and regenerate code after
writing anything that touches a `@freezed`/`@JsonSerializable`/`@injectable`/
`@ChopperApi`-annotated file, and fix all issues before calling a screen done.

## Architecture & conventions

- Feature-first, clean architecture: `lib/features/<feature>/{data,domain,presentation}`.
  See `docs/architecture.md` and the existing features for the exact shape —
  data sources, models (`@freezed` + `fromJson` + `part '*.g.dart'`, never
  `@JsonSerializable` stacked on `@freezed`), repositories returning
  `TaskEither<Failure, T>` from `fpdart`, use cases, blocs/cubits, pages.
- **Never `setState`.** All state — including small widget-local UI state —
  lives in a Cubit or Bloc. `grep -rn "setState" lib --include="*.dart"` must
  return nothing. See `tasks/lessons.md`.
- **Toasts, never SnackBars.** `ScaffoldMessenger`/`SnackBar` are banned;
  every user-facing message goes through `ChameleonToastMessenger` from
  `chameleon_ui`.
- Data-source calls that hit the network run on a worker isolate via
  `runApiCall`/`compute()` from `chameleon_core` — call
  `initIsolateBinaryMessenger` as the *first* line of every such worker.
- DI singletons resolved from `getIt` are provided to widgets with
  `BlocProvider.value`, never `create: (_) => getIt<X>()`.
- A route that depends on the DI container needs its widget tests to
  register stubs in `setUp` with `tearDown(getIt.reset)` — see
  `test/helpers/di_harness.dart`.
- `@visibleForTesting` means tests only. A debug-only production hook is
  public and gated on `kDebugMode`, not marked `@visibleForTesting`.

## Guardrails

Run `./tool/checks.sh` before every PR — it greps for the mistakes this
project's `tasks/lessons.md` documents (`setState`, `SnackBar`, `dartz`, raw
hex colors, leftover `TODO(chameleon)` placeholders, permission-macro/usage-
description drift). `./tool/verify.sh` runs analyze + test + format.

- Do **not** add new dependencies without asking first.
- Do **not** introduce a second state-management approach.
- Keep changes scoped to what's requested; don't refactor unrelated code.
- Preserve semantics labels, tap target sizes, and text-scaling support.

## Definition of done

A task is done when: `flutter analyze` is clean, `dart format .` has been
run, `./tool/checks.sh` passes, relevant tests pass, and any unavoidable
deviations from a design or plan are listed back to the user rather than
silently approximated.
